> 文档更新：2026-10-15。日常入口：`Start-Agent.cmd`，工作台：<http://127.0.0.1:8786>。首次克隆须先完成下文的依赖、数据库和本地凭据配置。

本程序位于 `E:\AI\codex\redbook_agent`，通过 `redbook_tools` 调用新闻采集、写稿、生图和草稿上传工具；PostgreSQL、草稿、图片、日志和专用浏览器 profile 保存在 `E:\AI\codex\redbook_runtime`。启动和运行不读取旧 `redbook_workflow` 目录。旧项目及其 `Start-Web-GUI.cmd`、`apps.cli` 仍保留，可继续人工使用。

## 快速开始

以下适用于本机已经配置的环境；首次部署先阅读“从 GitHub 部署”。

1. 双击 `Start-Agent.cmd`。脚本仅在 E 盘启动独立 PostgreSQL（端口 5433），然后启动本地 API 与已构建的前端。保留终端窗口，并手动打开下述网址；这个入口目前不会自动打开默认浏览器。
2. 用浏览器打开 <http://127.0.0.1:8786>。浏览网页可以用默认浏览器；小红书登录请在“连接与模型”中点击“打开专用浏览器”。两者的浏览器 profile 彼此独立。
3. 在“连接与模型”的“默认角色”分别选择智能体主控、写稿和生图模型。选择后自动保存，出现“默认角色已保存”即已落盘，重启仍保留；“继承原有配置”使用运行区本地配置。读取失败会保留已读取的绑定，可点角色区的刷新图标重试。右侧“本次模型”中，“应用于本次计划”只覆盖当前计划；“保存为默认模型”保存供以后新任务及重启使用的选择，不修改当前计划或运行中的模型。在此任务面板里仅改变下拉框但未点保存的选择不会保留。密钥不要放进代码、对话或 Git。
4. 回到“对话任务”，输入例如“生成 1 条每日新闻，只生成本地稿，不上传平台”。查看右侧计划，确认栏目、数量、交付方式后再点“确认并执行”。对话中的“运行播报”会持续更新当前阶段、耗时、各栏目完成数量和错误原因；生成结果见“草稿审查”。
5. 草稿页展示正文、图片、原始信源、日期和平台回读状态。来源、日期、内容、图文一致性应逐项人工核验。独立界面目前不执行公开发布；需要公开发布时请在平台人工确认。

浏览器刷新不会取消后台任务。API 只绑定 `127.0.0.1`，不要将端口直接暴露公网。当前专用浏览器 profile 在新运行区，必须单独登录；没有验证登录前，不要假定能上传。

### 一句话生成并保存草稿

> 使用 MiniMax 订阅作为主控和写稿模型，按当前生图绑定，速度优先，不同步额度。生成10条每日新闻，选题偏向国际冲突、科技产业、社会民生和财经产业；再生成1篇每日AI讯息、1篇每日全球事件关注图。检查真实性、日期与重复信息，使用专用 profile 保存到小红书草稿箱，不公开发布。

这段话只用于创建待确认计划。执行前检查右侧的数量、关键词、模型绑定和“保存到草稿箱”，再点“确认并执行”。栏目/数量不是成功保证；无近期合格材料、模型限额、平台登录或写入结果不确定时，会报告失败或部分完成。运行中从“运行播报”“运行记录”查看进度；恢复任务在原对话中发送“继续”，不要另开相同生成指令。

生成前关闭占用项目专用 profile 的手动浏览器窗口，默认浏览器的工作台可保持打开。不要同时运行两份后台或两个使用相同 profile 的平台任务。

### 在同一对话中继续任务

同一对话按业务目标保留计划、稿件与交付数量。右侧可选择目标，聊天区显示逐栏目的已交付、待上传、待核验和真实缺口：

- 要求不变：发送“继续”或“继续补齐剩下的”。沿用原计划及原 PostgreSQL 检查点，优先处理保留稿件，不整批重做。任务仍在运行时不会另起第二个执行器。
- 修改剩余部分：发送“剩下改成科技新闻，图片门槛只做参考”。核对右侧差异，可编辑候选，再点“确认修改并继续”；已交付稿件保持不变。放弃候选后可继续原计划。
- 明确加量：发送“额外再做3条每日新闻”，确认新目标数量；“再来3条”有歧义时会要求澄清。
- 新一批：发送“今天另开一批10条每日新闻”，建立独立目标，仍进行历史查重。跨日旧目标的完成数量不会自动充当今日新稿。
- 控制与查询：发送“暂停，先不要上传”“取消任务”或“现在进度如何”。控制在安全边界生效，在途提交不会硬杀浏览器；“已接收”不等于“已应用”。

刷新页面或重启后从原对话恢复，不删除数据库、检查点、租约或上传记录。平台写入结果不确定时须先核验；“继续”不能绕过登录、额度、风控或不确定结果保护。

新 PostgreSQL 对话默认自动压缩历史，已有手动策略保留。在“能力中心 → 记忆与上下文”可查看覆盖范围、快照和请求用量。压缩保留原始消息，任务状态与上传数量单独读取持久证据，不能由摘要决定。模型窗口未知时使用标为估算的保守预算；可在模型编辑中填写可选上下文窗口。自动压缩不会更换付费供应商、生成新闻或上传草稿。

### 指定新闻关键词与校准计划

例如输入：

> 生成5条每日新闻，关键词：伊朗、关税、芯片；保存到小红书草稿箱。再生成1篇每日AI讯息，关键词：DeepSeek、MiniMax。速度优先，不同步额度。

默认先用本地规则识别，不调用大模型。右侧“本次计划”会分别显示各栏目的关键词；这些词会进入实际检索与选题提示，而不只是界面说明。也支持“生成3条关于半导体的每日新闻”“围绕伊朗、关税生成5条每日新闻”。多词短语可以加引号，多个关键词用逗号或顿号分隔。

图片评分支持本地识别“图片门槛只做参考”“不需要对图片进行评分硬门槛”“关闭图片硬门槛”等表达，无需大模型校准。多次明确设置按最后一条指令处理；“不要关闭图片评分硬门槛”表示保留硬门槛。参考模式不因低评分阻止交付，仍检查文件有效性、正文、日期及事实；原版续跑沿用冻结策略，对剩余稿件改变策略需要确认修订，不直接改写旧检查点。

若本地识别不准确，点击右侧“大模型校准”：使用“连接与模型”中选定的**智能体主控模型**理解原始指令，显示候选及交付、平台、速度、图片评分和模型角色的对比。检查后选择“采用校准计划”或“保留当前计划”，最后另点“确认并执行”。校准和采用都不会启动写稿、生图、上传或额度同步。

校准正常执行一次业务模型调用，网络超时为60秒，无网络自动重试或付费供应商降级。上下文较长时后台先进行有界压缩；提供商明确返回上下文超限时至多进行一次紧急压缩并重试，相关请求单独记录。失败时保留原计划；无法映射的要求会明确提示，不允许悄悄忽略。校准记录保存在 PostgreSQL，刷新可恢复候选；服务重启时未完成的校准标为中断，需要手动重试。运行中的冻结计划不可原地改写，可为剩余工作提出修订并在安全边界交接。

校准支持现有模型的完整 ID、自定义模型引用和供应商名称，未要求换模型时保留当前绑定。人工编辑过的属性优先，模型的不同建议由用户决定是否采用。本次修复、测试范围与网络限制见 [模型、校准和稳定性检查](docs/plans/2026-10-12-agent-model-calibration-stability-review.md)。

## 实时了解任务

### 可选的阶段复用流程

新任务的计划编辑面板中，在“生成流程”选择“阶段复用（试用）”，保存计划后再确认执行。终端对应选项是 `--generation-pipeline-version staged_v2`，适用于本仓库 `redbook_tools` 的 `auto`、`agent` 命令；CLI 当前未注册 `create`。默认仍为 `legacy`；已有任务按原检查点版本恢复，不会因更新程序自动切换。

该模式使用真实 PostgreSQL 保存正文、定向修复和图片阶段结果。同一根任务恢复时优先复用输入、模型和规则未变化的结果；只修场景或评价时不重写已经通过的正文。AI 讯息按条目保存摘要，最多两批并行、每批最多六条，缺项只补对应条目。事实、时效、查重及图片硬错误的检查仍保留。

当前这是阶段性实现：跨栏目并行、持久化 READY 队列的边生成边上传、旧 `redbook_workflow` 的优化移植尚未完成。平台仍由既有串行交付流程处理。恢复保留不等于已上传，新增阶段计数也不代替平台回读确认。

数据库不可用时新模式明确报错，不降级。`STAGE_PENDING_OR_UNKNOWN` 或 `MODEL_CAPACITY_UNCERTAIN` 表示有请求结果需要核对，不能通过删库、换任务 ID 或清空租约盲目重发。当前需要人工核对并处理，尚无专用自助核对界面。详细完成范围和实测限制见 [提速实施报告](docs/plans/2026-10-10-news-performance-implementation-report.md)。尚未验证真实 10+1 端到端耗时，不承诺 30–40 分钟。

- 对话中的“运行播报”和右侧“最近一次运行”使用中文摘要。详细页面仍在“运行记录”；原始输出放在可展开的“技术日志”中。
- “产出记录”“通过审查”“平台保存”“回读确认”分别统计。未知数量显示“待记录”；本地成稿不等于上传成功，平台保存不等于回读确认。
- 点击“询问进度”，或者输入“现在进度如何”“卡在哪里”“完成了吗”，会返回本次任务的实际状态，不创建新任务、不调用模型。无法可靠预测时，不编造剩余时间。
- 无新事件时显示最近动态的时间；连接中断时保留最后状态并重连。任务结束后，已执行计划不能重复点击提交。
- 更新后请等待当前任务结束，再重启 `Start-Agent.cmd` 载入新版后台；不要为更新界面中止正在运行的生成/上传。旧后台仍运行时，新界面兼容显示阶段、耗时及已有平台记录，完整栏目统计和持久化进度问答在重启后启用。

## 信源健康

左侧「信源健康」可选择每日新闻、每日AI讯息或全部信源，点击「检查信源」逐项检测。页面自动显示进度并刷新结果，支持搜索及「仅请求失败」筛选；每个来源都有检查时间、近期材料数、耗时和处理建议。

该功能只读，不调用模型、不生图、不同步额度、不生成或上传帖子，但会消耗新闻 API 的请求次数。缺少密钥、未选择、未启用、没有近期消息和请求失败分别显示。AIHOT/RSSHub 未启动时应按需启动对应服务，检测不会自动启动它们。

每日新闻默认主题精简为「国际冲突、科技产业、社会民生、财经产业」。明确提供的关键词会替换默认主题，例如「生成5条每日新闻，关键词：女性权益、芯片；保存到草稿箱」。每日AI讯息新增 Google AI、AWS AI、Microsoft Research、MiniMax 官方公告及 OpenAI Codex 发布流，继续保留两日门禁、历史查重、同信源最多两条和热度核验，不固定凑八条。

设计与验证记录见 `docs/plans/2026-10-06-source-diagnostics-ai-coverage-design.md`。

## 本地 AIHOT 信源

“每日AI讯息”可额外读取本项目 `tools/AIHOT` 的开源 AIHOT。运行前执行 `scripts/manage_aihot.ps1 -Action start -Worker`，结束后执行相同脚本的 `-Action stop`；站点地址为 <http://127.0.0.1:8768>。独立运行区的 `.env.gui` 已配置本地 API 地址。AIHOT 使用另一套 E 盘 PostgreSQL（5434），数据继续在 `E:\AI\codex\AIHOT-data`；两个程序不要同时启动两份服务。若该服务未启动，智能体会报告该聚合信源的连接失败，并继续尝试其余信源。AIHOT 仅提供可核验原始网址和发布时间的候选线索，最终仍由智能体执行时效、查重与内容质量检查。

另外默认启用 AIHOT 公开日报，无需启动本地 AIHOT。显式配置 `AI_DIGEST_SOURCE_IDS` 时仍遵循白名单。日报只提供发现线索：程序按单篇文章解析标题/摘要/外链，有限并发核验受信任官方原文与发布时间，再执行两日时效及历史查重。未核验的线索不会当作官方消息，日报日期也不能替代原文发布时间。信源冷却到期后有限探测恢复，不因一次失败永久停用。

## 安装与更新

### ChatGPT 订阅生图

运行区 `.env.gui` 的 `OPENCODEX_IMAGE_ENABLED=1` 启用本机 OpenCodex 图片连接；在“连接与模型”的生图角色选择 `opencodex:gpt-image-2`，主控和写稿可继续使用 MiniMax。额度显示为“订阅额度未查询”，不是免费无限额度。新连接最多 2 并发，普通生图可用 `OPENCODEX_IMAGE_FALLBACK=minimax` 切换 MiniMax Token Plan，但不会切到付费 API。

AI鸡蛋/AI福利沿用每日羊毛栏目，通过运行区 `assets/wool` 的构图参考与对应厂商人设编辑封面。成功图片持久化缓存；超时或进程中断后不能确定是否完成的请求不会自动重发。双图编辑不自动降级成普通文生图。OpenCodex 更新不会覆盖工具包，但代码或接口变化时必须重新核验，不能保证未知版本自动兼容。

参考图与人设图必须位于独立运行区，不能只复制代码。新旧入口使用同一个 E 盘 `OPENCODEX_IMAGE_LOCK_DIR` 和 `OPENCODEX_IMAGE_STATE_DIR`，共同限制两路并发；响应不确定时，换稿件 ID 也不能绕过重复提交保护。遇到 `OPENCODEX_PREVIOUS_REQUEST_UNCERTAIN` 时先核查原请求，不要删除记录盲目重试。

现有 E 盘虚拟环境、前端构建和 PostgreSQL 已准备好。重新构建前端：

```powershell
Set-Location E:\AI\codex\redbook_agent\frontend
npm ci --cache E:\AI\codex\redbook_agent\.npm-cache
npm run build
```

重建独立 Python 环境时，在 E 盘执行：

```powershell
Set-Location E:\AI\codex\redbook_agent
$env:PIP_CACHE_DIR="$PWD\.pip-cache"
$env:PLAYWRIGHT_BROWSERS_PATH="$PWD\.playwright-browsers"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`tools/redbook_tools` 是本仓库自带的领域工具包；安装 `requirements.txt` 后，`python -m redbook_tools --help` 可查看人工命令，不需要旁边存在旧工作流目录或另一个工具包目录。工具包代码是当前独立工具包的版本快照，旧项目入口仍保持原实现，**后续修复尚不会自动双向同步**；在正式切换旧 CLI 到共享实现前，应分别运行新旧入口回归。不要删除旧目录或其数据。

独立数据库文件位于运行区 `data/knowledge/postgresql-local/pgdata`。首次部署才运行运行区的 `data/runtime/postgresql/initialize.ps1`，它拒绝覆盖现有数据库。日常启动只使用 `Start-Agent.cmd`。旧知识库已非破坏性备份和导入，新旧 PostgreSQL 分别使用 5432/5433；后续旧项目新增数据不会自动同步，需要单独执行增量迁移。

## 验证

### AI鸡蛋候选图库

左侧“AI鸡蛋图库”可浏览候选图、参考原图与厂商人设。候选图先查看大图和作者来源，确认成年、非露骨及使用权限后才可入选；“参考原图”可指定当前使用的构图图。入选后，生成 AI鸡蛋/AI福利时自动用 ChatGPT 订阅进行双图描改，人物身份取自对应厂商人设，禁止付费 API 降级。图库数据在 `E:\AI\codex\redbook_runtime\assets\wool`，与旧程序的人工批准状态分开保存。新界面和新路由需重启本程序后载入，不要中断正在运行的任务。

```powershell
Set-Location E:\AI\codex\redbook_agent
.\.venv\Scripts\python.exe -m pytest -q tests
$env:PYTHONPATH=(Get-Location).Path
Set-Location E:\AI\codex\redbook_agent\tools\redbook_tools
E:\AI\codex\redbook_agent\.venv\Scripts\python.exe -m pytest -q tests
```

工具包的旧 Web 兼容入口会调用本仓库 `backend` 的冻结计划服务，因此单独测试工具包时需保留上面的 `PYTHONPATH`；它不指向旧工作流。自动化测试可能跳过需要显式授权、真实数据库或外部账号的案例，不能当成平台端到端验收。

pytest 会在 E 盘创建临时运行目录和独立的 PostgreSQL 测试数据库，并初始化知识库及 LangGraph 检查点表，结束后删除测试数据库和临时凭据。测试数据库使用本机管理连接；不会修改正式数据库的访问规则。生成任务只检查当前账号的向量索引就绪状态，其他命名空间的待索引记录不会阻止任务。

本地运行区、`.env.gui`、数据库凭据、浏览器 profile、草稿图片、日志和模型缓存均不得加入 Git。新程序的 `.gitignore` 与运行区的忽略规则已覆盖这些路径；提交前仍需检查暂存文件清单。没有完成新 profile 的真实平台登录、上传与回读验证之前，不应将“草稿已上传”作为测试通过结论。

## 密钥与 Git 安全

- 真实 API Key、密码、Token 只存放于运行区 `.env.gui`、环境变量或本地凭据文件。不要在 README、聊天、测试 fixture 或运行截图中填写真实值；示例只使用 `YOUR_API_KEY` 等占位符。
- `.gitignore` 排除本地环境、账号池、Cookie、浏览器 profile、数据库导出、日志、图片和工具二进制，但不会让已跟踪的文件停止跟踪，也不能发现代码中任意命名的密钥。
- 提交前检查 `git status --short`、`git diff --cached --stat`、`git diff --cached --check`，并扫描暂存内容中的真实凭据。`git ls-files --cached --ignored --exclude-standard` 可查已跟踪但被忽略的路径；不要把这个清单一律删除，部分可能是合法的源码或项目文档。
- 密钥若曾进入 Git 历史，应立即撤销/轮换，再处理历史；新增忽略规则不等于历史已经清理。不要将运行区加入源码仓库，也不要使用 `git add -f` 强行加入私有文件。

## 从 GitHub 部署

本仓库包含后端、前端源码、测试、领域工具包及无凭据的数据库初始化/管理脚本，不包含本机已经准备好的运行区。克隆源码不等于自动获得可用的模型账号、数据库或浏览器登录态。

```powershell
Set-Location E:\AI\codex
git clone https://github.com/bty3052771076-tech/redbook_auto_agent.git redbook_agent
Set-Location redbook_agent
```

1. 将仓库克隆到 E 盘，按上述命令建立 `.venv`、安装根目录 `requirements.txt` 并构建 `frontend`。Python 需要 3.10 或以上；Node.js 需满足 Vite 7 的版本要求。pip/npm/Playwright 的下载缓存也应设置到 E 盘。
2. 新建 `E:\AI\codex\redbook_runtime`。将 `deployment/postgresql/initialize.ps1`、`manage.ps1` 放到运行区的 `data/runtime/postgresql/`。该目录还需自行准备 PostgreSQL 18.6 的 `18.6/pgsql/` Windows 二进制及匹配的 pgvector 扩展；本仓库不分发数据库二进制。不要覆盖已经存在的运行区和数据库。
3. 仅在全新数据库部署中执行 `initialize.ps1`，再执行 `manage.ps1 -Action start`。凭据会在运行区生成，脚本拒绝覆盖现有数据库。用本仓库 Python 在本地执行 `from src.knowledge.store import KnowledgeStore; KnowledgeStore.from_env().ensure_schema()` 前，设置 `KNOWLEDGE_DB_CREDENTIALS` 为运行区的 `data/knowledge/postgresql-local/connection.json`，以创建应用表结构。生产必须使用 PostgreSQL/pgvector，不降级。
4. 运行区 `.env.gui` 中填写本人的供应商密钥和模型配置；不要提交该文件。ChatGPT 订阅生图需要另行准备本地 OpenCodex 和已授权的账号连接；仅克隆本仓库不会获得该连接。参考图/人设图、地图 GeoJSON、可选 AIHOT/RSSHub 等外部服务也需要自行配置。
5. 启动 `Start-Agent.cmd`，通过连接页面在专用 profile 中完成平台登录，然后先验证本地生成和草稿上传。首次部署的完整生成与平台链路需要部署者实机验证；本仓库的自动化测试不能替代账号权限和平台审核结果。

现有本机 `.venv` 已改用仓库内 `tools/redbook_tools`。`Start-Agent.cmd` 使用 `scripts/manage_postgresql.ps1` 从本项目的 PostgreSQL 副本管理原运行区数据库；新部署也需要准备该二进制目录。更新时先等待当前任务结束，不要同时运行两份后台竞争同一 profile。
