# 每日新闻数字核验与导语完整性最小修复

## 范围与证据

仅修改 `src/workflow/create_post.py` 的数量核验、静默删句、句内去重、导语门禁及既有一次重写的错误路由。不修改配图事件、生成系统提示、场景审计、智能体核心、上传或生产状态。

GitNexus 只索引旧 `auto_redbook`，未覆盖独立 `redbook_tools`。旧图对数字核验、去重及正文转换返回 CRITICAL，对导语门禁返回 UNKNOWN；不能据此认定实际调用范围。文本确认正文转换也用于材料模式和每日我去，需要保持失败关闭。

真实案例：

- `3c130827312c47e2b0151812acdcc608` 正文从“当被问及”开始，缺少航班事件的导语；采集时间不能证明正文中的具体事件日期。
- `7da8be76fcf74456bff6b43c4bb5a20b` 正文从“事件现场”开始。来源明确含 `More than 100 militant settlers` 与 `Three Israeli security officials`，旧数字核验却将中文 `超过100名`、`3名` 当作无依据。

旧核验按字符子串匹配，随后删除含不支持数字的整句；相似句去重也会用较长后句替换首句。离线构造“完整导语 + 真实残稿”能够复现导语消失。未保存原始模型响应，不能据此断言实跑时模型一定输出过完整导语。

## 行为约定

1. 数字按“数值、单位、上下界/近似限定”共同核验；支持已明确实现的英文数词、中文数词和人数量词等价，不以数字在来源任意位置出现作为证明。
2. 保守处理未知、模糊或未实现的表达，返回不支持。不得把大数词的局部片段当作小数值；人员和时长单位不能互相证明。日期必须匹配完整月日，发布时间元数据不能充当事件日期。
3. `_daily_news_remove_unsupported_numeric_sentences` 保留兼容入口，但不再删句。无法核验时抛出 `_DailyNewsNumericClaimError("unsupported_numeric_claim")`。
4. 候选审查将该异常转换为质量问题，进入已有一次重写；修订稿再次核验，仍失败则拒绝该候选，不落为成功稿。每日我去和直接转换调用保持拒绝，不新增重试循环。
5. 句内去重只移除规范化后相同的句子，并保留首次出现的导语；共同主体、字符相似、后句更长均不足以删除前句。
6. “当被问及 / 被问及 / 事件现场 / 同日”等无前置事件的正文开头返回 `missing_lead_event`；完整导语后的这些细节不受影响。

这是数量证据与导语结构门禁，不替代完整事实核验，也不降低已有真实性、日期、查重或评分标准。未修改其他清洗器；另观察到末句清洗与裁剪的独立风险，留待单独评审。
