# 智能体模型、校准与稳定性检查

日期：2026-10-12

## 范围和约束

- 对象为独立 `redbook_agent` 及其内置 `tools/redbook_tools`，不修改旧工作流或迁移运行数据。
- 保留现有模型注册表、PostgreSQL 对话记录、执行身份与启动锁；不增加业务模块、数据库或依赖。
- 不启动内容生成、上传、发布或额度同步；不重启当前 8786 服务和正在运行的任务。
- 使用 systematic-debugging、GitNexus 和隔离并行审查；改动前做影响分析。共享计划、脱敏和任务启动涉及高影响路径，需要全量回归，图谱不替代实机证据。

## 已确认问题与处理

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 默认模型重开后丢失 | 下拉只更新组件内存，离开页面前未保存就丢失；已显式保存的数据并未丢失 | 默认角色按单角色立即保存；保存中禁用；失败不假装成功；任务覆盖仍显式应用 |
| 校准把可用模型标为不可用 | 返回完整模型 ID，却只按供应商名称匹配 | 先精确匹配模型引用，再匹配供应商；检查角色、类型、可用性；自定义模型共用现有目录 |
| 人工选择后仍被校准错误阻止 | 人工覆盖恢复了模型，但被拒建议的错误仍残留 | 只给最终仍未解决的模型字段报告错误 |
| 校准来源标注全部待核对 | annotations schema 没有定义对象和 evidence_ids，提示词存在歧义 | 明确对象数组格式；旧格式仍作为可编辑候选处理，不以原文引用问题丢弃整个计划 |
| 速度优先被标为不可执行 | 模型输出 fast，执行器只支持 speed | schema、能力列表、提示词统一支持值；未知值继续展示为待修正，不暗中放宽执行边界 |
| 历史计划越多，配置读取越多 | 每个历史版本重复读取目录及计算配置指纹 | 只在一次读取请求内复用目录与指纹；下一请求重新读取，不使用长期缓存 |
| 同名密钥漏脱敏 | 脱敏集合按变量名合并，与子进程环境优先级不一致 | 收集文件与环境的所有敏感值，按长到短替换，避免前缀值遮挡 |
| 数据库恢复后多个管理器 | 懒初始化未互斥 | 初始化锁与锁内复查，异常释放锁，不改变 PostgreSQL 必需策略 |
| 未启动线程留下排队任务 | 落盘后 Thread.start 失败，原执行身份无法正常续接 | 只在证实未启动时撤销该次启动记录，并阻止延迟线程执行；复用原执行身份重试；不回放已启动或不确定任务 |

## 验证

针对性测试已覆盖：模型选择保存、刷新和实例重建；保存失败与并发保存；默认和任务覆盖隔离；自定义模型与图片引用；人工覆盖；校准采用和版本冲突；配置请求内复用但跨请求失效；脱敏冲突；并发初始化与线程启动失败。

真实 MiniMax 订阅测试在独立 PostgreSQL namespace、临时运行目录和 headless 浏览器执行。最终一轮校准 15.188 秒，候选无字段错误与标注诊断；编辑保存并刷新 0.312 秒，总计 17.797 秒，模型调用一次，生成与平台写入均为零。

前两轮实机测试发生连接失败，原计划保留；后续单次测试成功。未关闭 TLS 校验，未启用自动重试或付费回退。成功一轮不代表外部网络永不失败。

## 使用更新

前端构建完成后刷新页面可使用默认模型自动保存。后台修复需要等当前任务结束后重启 `Start-Agent.cmd`。已有历史校准候选不批量重写；针对旧错误重新校准或人工编辑后确认，避免更改已经冻结的任务。
