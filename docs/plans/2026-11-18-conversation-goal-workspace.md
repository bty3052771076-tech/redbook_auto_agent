# 会话目标与多轮生成

## 界面

任务对话顶部显示当前目标、生命周期、实绩/目标篇数和轮次。设定目标使用独立表单；对话、动态、工具与产物仍分别显示。工具与产物可切换到仅本轮视图。会话总量不因开始新一轮而归零；审批仍在对话页独立处理。

人工计划、草稿审查、运行记录、连接与模型、能力中心、信源健康和图库保留原接口及路径。目标不切换供应商，不启用权限，不发布平台内容。

## 目标运行

目标参考 [Codex Goals](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex) 的会话级持久化和证据驱动续跑设计。使用现有 PostgreSQL 对话会话、工具账本和 LangGraph 检查点；不把目标写入全局记忆，不切换到旧批处理。

- 每个会话有一个当前目标，开始、编辑、恢复、暂停和清除由用户控制。更新时核对目标版本，防止另一标签页覆盖。
- 验收可选本地生成、审查通过、平台草稿已确认或人工验收。前三者只计目标设定后的成功记录，按稿件 ID 去重。没有正向回读的上传不能计入。包含风格、选题比例等无法自动核实的要求，选择人工验收。
- 每轮结束且没有待确认请求时，才比较交付与目标。若尚未完成且有新证据，沿同一个检查点推进下一步。没有新增证据或达到轮次上限时停下，不把它当成完成。轮次上限不是 token 配额。
- 暂停目标只暂停自动推进；“暂停对话”用于中止正在执行的轮次。清除目标保留现有消息、审批记录、稿件和平台回执。重启后读取持久化状态，不因为页面打开就重放旧动作。
- 同一个会话的下一条普通指令可形成新一轮。审批中断和恢复属于同一轮；已完成、重复或未知结果的动作仍由账本保护，不因开启新轮而重跑。新一轮不继承上一轮的临时授权。

## 验收

1. API 与 PostgreSQL：生命周期、重复命令、版本冲突、权限检查和持久状态。
2. 真实 LangChain 与隔离 PostgreSQL：同一对话两轮生成不同稿件、原稿保留、新一轮重新请示；同一目标跨审批自动推进，数量达标后结束。
3. 浏览器：桌面及手机设定和查看目标，刷新保留状态，暂停、恢复和清除，本轮与累计产物区分，保留原审批及导航能力。
