## 2. 已接入的优化

1. **修哪里就重写哪里。** 场景不通过时，只请求 `image_event` 补丁；评价问题只改评价。补丁核对原版本及允许字段，重新审核时保持已通过的正文不变。文本与场景各最多一次定向修复，不循环整篇重写。
2. **同一任务按阶段恢复。** PostgreSQL 保存正文、修复结果与图片清单，按原文、模型、规则、权限及任务隔离键复用。图片恢复检查文件和哈希；已完成结果可以不再调用模型。不能确认结果的远端请求不自动重复派发。
3. **AI 摘要局部补齐。** 按 `item_id` 绑定原信源，每批最多六条、最多两批同时摘要；缺少一个条目只补它，不让模型改写网址和发布时间。两日日期窗口、历史查重和最终质量门禁继续执行。
4. **共享并发名额。** 新模式中 MiniMax 文本入口最多 5、生图最多 2，并由真实 PostgreSQL 跨进程协调；混合或未知文本提供商使用更保守的共享组。进程心跳丢失后暂停核对，不释放可能仍在执行的远端请求。
5. **可解释的进度与计时。** UI 分开显示正文通过、图片就绪、正在修复、候选未通过；平台保存/回读仍单独计数。阶段区间与模型适配器调用区间分开，Token 数可记录，密钥不记录。SDK 内部重试尚不可观测，不能把适配器计数宣称为全部 HTTP 请求数。
6. **保守的事实核查扩展。** 不可变原文与引用区间、万/亿及瓶数和百分点的 Decimal 换算、角色/主体/计划与已发生等反例已覆盖。该规则集不是完整语义证明；历史 54 次数字拒绝仍未完成金标归类，不宣称已解决所有数字误杀。

源码位于 `tools/redbook_tools/src/workflow/`、`src/ai_digest/incremental.py`，及智能体的 CLI、计划契约、前端计划/进度模块。没有更换语言、没有安装新依赖，没有在 C 盘安装软件。

## 3. 如何选择

- 等当前任务结束后，重新启动 `Start-Agent.cmd`，打开 `http://127.0.0.1:8786`。不要强制结束运行中的上传来更新程序。
- 新建任务后编辑计划，在“生成流程”选择“阶段复用（试用）”，保存后另行确认执行。
- 嵌入工具的 `create`、`auto`、`agent` 命令支持 `--generation-pipeline-version staged_v2`。它不替代其他任务参数，也不改变费用或发布权限。
- 默认值是 `legacy`。旧检查点即使在新的默认配置下恢复，也按原版本解释，不能借恢复偷偷更换流程。
- `STAGE_PENDING_OR_UNKNOWN` / `MODEL_CAPACITY_UNCERTAIN` 需要核对原请求；现阶段尚无专用自助核对界面。不要清表后盲重发。

## 5. 未完成项与后续验收顺序

1. 补齐历史 54 次数字拒绝的证据金标及跨语言实体核对，完善事实不确定时的一次定向证据判定。
2. 完成显式运行时配置注入，证明模型/代理/权限没有 `os.environ` 串扰后，再启用新闻与 AI 跨栏目并行、3:1 公平调度。目前栏目仍串行。
3. 接入持久化 READY 队列、唯一平台消费者和跨进程 profile 锁，测试点击保存后崩溃与不确定回执。当前不具备新的边生成边上传流程，也不能把现有串行上传冒充这部分完成。
4. 补齐原文 304 缓存、错误负缓存、核对界面及持久化入队的五个断点测试。当前阶段恢复测试不覆盖未实现的 READY/平台崩溃流程。
5. 逐模块适配旧 `redbook_workflow`。两边此前已存在较大接口差异，不能覆盖复制整个工具目录，也不能让工作流依赖智能体的绝对路径。本轮仅验证旧程序回归，未移植优化。
6. 完成真实费用/profile 确认后，安排一次 10 新闻 + 1 AI 的草稿链路及受控断点恢复；随后才开展至少三组同条件性能对照。未达质量/完整性与性能目标前，新模式不设为默认。

这些是实际剩余工作，不是本轮已经完成的能力。数据库新增表是可选流程的增量迁移；回滚时停止新增 v2 任务即可，保留缓存与检查点，不删除生产数据。已有 v2 任务不能强制改用旧解释器重跑。
