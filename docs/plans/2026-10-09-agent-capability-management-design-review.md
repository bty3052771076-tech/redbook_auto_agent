# 智能体能力中心：设计复核与实施边界

日期：2026-10-09，香港/北京时间。状态：设计交付，完整实施尚未验收。

适用程序：`E:\AI\codex\redbook_agent`。数据区：`E:\AI\codex\redbook_runtime`。

详细规格：[主设计](2026-10-08-agent-capability-management-design.md)。页面及 42 项验收场景：[界面与验收](2026-10-08-agent-capability-management-ui-acceptance.md)。本文件补充用户操作路径、关键一致性要求和当前实施状态；冲突时采用本文件的更明确约束。

## 1. 用户目标与交付范围

目标是把智能体目前不可见的工具、MCP、SKILLS、记忆、知识库、上下文和断点变成可查看、可解释、可管理的资源。管理不仅指有开关，还必须能回答：

- 有什么能力，具体做什么，是否已经接到真实执行入口？
- 为什么本次选择它，实际是否调用，失败在什么步骤？
- 修改、停用或遗忘后，下一次任务和恢复任务分别受到什么影响？
- 新闻生成使用了哪些偏好、历史材料、技能版本和浏览器 profile？

本轮只完善设计，不继续修改业务代码、不安装依赖、不启动生成或平台写入、不推送 Git。已有工作树改动保留，不回滚。历史数据、稿件、图片、项目文档都保留。

成功标准不是展示很多名称，而是页面状态与实际执行可相互核对。只有后端实施和完整验收通过，才能称“可管理”。

## 2. 方案选择

| 方案 | 优点 | 不采用或采用的原因 |
| --- | --- | --- |
| 各模块增加一个配置表 | 工作量少 | 配置分散；无法证明开关和记忆影响执行 |
| 统一能力中心，保留领域工具 | 管理集中，原工作流和恢复机制保留 | **推荐**，新增控制层而不是重写智能体 |
| 换成另一个通用智能体平台 | 获得平台已有管理界面 | 迁移范围大，容易破坏 profile、稿件保留和 PG 断点 |

沿用 React/Vite、Lucide、FastAPI、LangGraph、PostgreSQL/pgvector 和现有模型供应商设置。MCP 是工具接入协议，SKILL 是指导材料，记忆是持久信息，三者不能共用一个“安装插件即可执行”的权限模型。

## 3. 用户入口与具体位置

侧栏只增加一个“能力中心”，紧邻“连接与模型”。原有对话、草稿、运行记录、信源健康和图库保持位置。

```text
侧栏                 主工作区
对话                 能力中心                         刷新状态
草稿                 概览 工具 MCP SKILLS 记忆与知识库 调用与变更
运行记录             ------------------------------------------------
连接与模型           搜索/筛选
能力中心  <选中>     名称       状态       使用范围     最近调用
信源健康             新闻生成   待检测     工作流       任务链接
图库                 草稿保存   已配置     工作流       任务链接
                     ------------------------------------------------
                     分页                 选中行 -> 右侧详情抽屉
```

布局以表格、页签、信息带和抽屉为主，不做装饰性大卡片。沿用白色、灰色分隔、青绿主操作，故障用橙红，同时保留文字状态。页面标题 24px，列表 13–14px，详情标题 19px，字距 0，圆角 4–6px。

1440px：列表和 420px 详情并列。1024px：详情覆盖工作区。390px：全屏详情，保留返回按钮。路径、URL、英文 ID 换行，不通过缩小字号挤入容器。

## 4. 六个页签的管理内容

| 页签 | 用户能看到 | 用户能操作 | 不允许暗中发生 |
| --- | --- | --- | --- |
| 概览 | 目录数量、真实健康、待处理问题、运行目录/profile、最近调用 | 刷新保存状态、打开故障详情 | 启动模型、浏览器或 MCP 来填充首屏 |
| 工具 | 内置/MCP 工具用途、权限、阶段、依赖、真实绑定、调用证据 | 启停、允许参数、检查、停止后续调用 | 未接入工具标成可用；关闭顶层工具但内部继续调用 |
| MCP | 连接配置、协议、工具目录/schema、批准范围、进程状态 | 添加、编辑、导入预览、发现、批准、退役 | GET 启动服务；导入后自动运行命令或授权工具 |
| SKILLS | 正文、附件、来源、版本/hash、适用栏目、加载记录 | 导入预览、保存新版本、启停、选择模式、退役 | 自动安装仓库；读取正文就执行 scripts |
| 记忆与知识库 | 偏好、原始资料、检索、摘要范围、任务断点 | 修正/停用/遗忘偏好、用途排除、检索测试、压缩、恢复跳转 | 用历史稿件替代新闻事实；删偏好时删除稿件 |
| 调用与变更 | 调用时间线、父子关系、错误、证据、资源变更 | 筛选、查看详情、跳回任务 | 从当前配置伪造历史调用或显示模型私有推理 |

模型、信源和图库仍由原页面管理，能力中心提供跳转和依赖状态，不复制这些表单。

### 4.1 工具详情抽屉

顶部显示名称、稳定 ID、配置版本、启用状态、健康结果时间。下方依次为用途/允许阶段、输入输出字段、权限和费用影响、依赖、最近调用、允许修改的参数。

使用真实适配器表登记 `adapter_id` 和支持的入口。目录声明 `workflow` 之前，必须有该适配器的调用测试；只有 schema 或名称的工具显示“未接入”。必要审稿和产物保留不能被普通开关绕过。

“检查可用性”与“试运行”分开。前者只验证配置、只读依赖或协议；后者先显示输入和真实影响，明确确认后只执行一次。平台上传并发固定 1，不能在此页面调成并行。

### 4.2 添加 MCP 的完整路径

添加连接 -> 选择 stdio/Streamable HTTP -> 填已有程序路径或 URL -> 保存为未启用 -> 检测并发现 -> 查看 schema 和目录差异 -> 批准只读阶段/用途 -> 加入可用集合。

默认不支持的 OAuth、旧 SSE 或未知导入字段直接列出，不制造空壳按钮。导入预览不返回密钥明文：后端先存入加密凭据区，前端只获得“已配置”和一次性导入引用。秘密不写入 PG 版本正文或诊断日志。

工具 ID 带连接 ID，避免同名串调用。工具目录完整分页后才判断移除；schema 改变使旧批准失效。协议兼容性依据实际安装 SDK 与握手结果，不写死“所有服务必须 initialize”或固定最新协议版本。

按任务和不可变连接版本复用 stdio 会话；无在途请求且空闲 60 秒、任务结束或明确退出时关闭本程序拥有的进程。GET 不创建进程；不得按 Python/Node 名称批量杀进程。HTTP 认证禁止跨 host 重定向转发。

### 4.3 管理 SKILLS 的完整路径

导入文件夹/ZIP -> 预览来源、文件、正文/附件 hash、冲突与脚本 -> 原子保存版本 -> 启用 -> 在对话选择关闭/自动/手动。

手动至多 3 项；自动依据栏目别名、标签和关键词选至多 3 项；默认保持关闭。受限 frontmatter 无法解析时明确拒绝。导入检查 ZIP 路径穿越、符号链接/重解析点、解压总量及文件数。

用户版和随应用版分组。修改随应用版创建副本；修改用户版新增不可变版本。正文和附件均参与 hash；只更新附件也产生新版本。附带脚本不会因为正文被加载而获得执行权限。

## 5. 记忆不是一个混合列表

“记忆与知识库”使用四个二级页签：

| 分类 | 示例 | 管理方式 |
| --- | --- | --- |
| 长期偏好 | 普通新闻 150–220 字；配图尽量无字 | scope、来源、有效期、确认、修正、停用、遗忘 |
| 资料库 | 已发布内容、统计、原始报道、审核证据 | 原文/当前片段、来源、版本、检索用途、纠错注释 |
| 对话上下文 | 原消息、摘要、近期后缀、有效约束 | 查看实际组成、压缩策略、压缩历史、纠正 |
| 任务断点 | 已生成/已审查/已保存草稿的产物 | 查看冻结依赖、缺失项和恢复入口 |

偏好优先级：程序权限/合规约束 -> 本次用户明确要求 -> 更具体作用域的已确认偏好 -> 全局已确认偏好。模型推断须先确认；不能从一次临时要求自动变成全局默认。

资料详情同时展示发布时间、采集时间、来源、namespace 和原始内容。纠错作为有证据的注释，不覆盖来源原文。用途排除在 SQL 检索阶段生效，可以排除事实引用但保留历史查重。

检索排序分数不命名为可信度。空文本跳过、待索引和索引失败分别计数。嵌入模型继续使用当前实际绑定；页面不硬编码历史统计数。

### 5.1 遗忘及隔离

遗忘是一项有引用关系的操作：停用该偏好 -> 标记关联摘要/缓存失效 -> 后续上下文重新组装 -> 记录影响范围。已有在途模型请求无法撤回。

失效必须限定 namespace、账号/栏目/对话和来源引用。旧摘要缺乏关联信息时，只让受影响范围进入“需重建”，不能一条测试偏好使所有生产摘要失效。原始消息和稿件保留，重建时继续应用遗忘规则。

### 5.2 上下文可见性

分别显示“历史已保存”“本次已选择”“实际发送至模型”。没有有效摘要时不能静默丢掉第 17 条之前的消息，也不能把保存于计划 JSON 的字段称为已经注入模型。

压缩率比较同一有效上下文范围：压缩前全量有效内容，对比压缩后摘要、未压缩后缀及固定提示。token 估算与供应商账单分开。压缩无收益、不需要压缩、revision 冲突、模型失败分别展示；失败时不删除原始信息。

## 6. 对话中的“本次能力”

位于右侧计划内，“执行边界”上方，可折叠。它管理本次任务，而不是全局默认。

```text
本次计划
  每日新闻 10条
  每日AI讯息 1条

本次能力                                      调整
  工具     新闻检索、写稿、生图、审核、草稿保存
  SKILLS   关闭 | 自动 | 手动       已选项/版本
  偏好     本次生效的条目            查看来源
  知识库   执行时检索 / 实际命中项
  模型     主控、写稿、生图的实际绑定
  浏览器   完整 user-data-dir 和 profile-directory
  检查     具体阻塞项                处理

执行边界：保存草稿
确认并执行
```

未执行时可以调整本次能力，不改动数量、关键词或已有大模型校准结果。确认时冻结；执行后只读。模型、profile 路径不能仅写“当前配置”，要能打开详情定位实际值。

使用状态必须分层：候选 -> 本次已选 -> 已加载正文/附件 -> 已调用/调用结果。预检不能预造检索命中数；尚未执行显示“执行时检索”。旧任务没有记录时显示“该版本未采集”。

实时播报由结构化事件生成，例如“已加载写作技能 v2”“图片生成排队中”“草稿提交后状态待核对”。不得由主模型随意描述成功来代替真实证据。

## 7. 执行与数据一致性

控制面：目录、配置、版本、检测、审计。执行面：现有领域工作流、统一策略入口、真实 MCP 适配器。二者通过 PG 的不可变资源版本和任务快照连接。

```text
GUI / 智能体 CLI
  -> 预检 -> 冻结计划/资源版本 -> 已有 LangGraph
  -> ToolDispatcher -> 权限/依赖/撤销校验
  -> 领域工具或 MCP -> 产物/证据 -> 调用记录 -> 运行事件
```

必须同时覆盖顶层工具和内部可管理子能力，跨线程保留 run_id、parent_call_id 和策略上下文。递归包装不得重复生成或重复上传。普通人工脚本保留原领域接口，不强制迁移到新页面。

| 操作 | 原子边界/生效规则 |
| --- | --- |
| 配置保存 | expected_revision 检查、不可变版本与变更记录同一 PG 事务；冲突 409 |
| 计划确认 | 先确定稳定 run_id，再一致读取资源版本并持久化快照，最后启动 worker |
| 普通停用/编辑 | 新任务采用新版本；旧任务使用冻结版本 |
| 停止后续调用 | 撤销记录原子保存；执行入口判断未提交/已提交边界；不丢在途结果 |
| 上传不确定 | 先读回核对，不因页面超时重发；保留原 operation_key 和证据 |
| 恢复 | 读取原 run_id 的快照及断点；只处理未完成步骤，不整批重跑 |
| 退役 | 停止新引用；保留活动、暂停和可恢复任务引用的旧版本 |

引用数量区分正在运行、暂停待恢复和历史任务；不能把所有历史快照都称作活动任务。任何撤销/权限拒绝进入可解释的阻塞状态，不能被生成重试循环反复调用。

数据库事务不跨网络调用。调用意图提交在副作用之前，结果提交在其后。崩溃留下 running/uncertain 时由恢复核对，不能直接标成功。网络、模型失败有独立有限诊断，不与业务自动生成混为一个任务。

生产只使用 PostgreSQL/pgvector；不可用时写操作真实失败。静态目录和带时间的只读缓存可以显示，但不能切换 JSON/SQLite 假装记忆服务正常。秘密只保存引用；大型图片、HTML、日志保存在 E 盘运行数据区。

## 8. 接口与可操作错误补充

主设计已列全部资源接口；本次补充实现必须对齐的细节：

- 列表 50 项默认、200 上限，筛选必须先进入 SQL 再分页，游标稳定且 scope 一致。
- 调用详情提供 `GET /api/capability-calls/{call_id}`；深链接不能仅搜索当前第一页。
- 有副作用的试运行采用独立 POST 与幂等键，返回任务 ID；不复用“检测”接口偷偷生成。
- 导入 secret 只返回不可用明文的 preview 引用；错误、导出、stderr 下载持续脱敏。
- 长任务幂等键关联 namespace、动作、输入 digest；同键不同输入返回 409。
- 对输入缺项/类型错误明确 422；数据库故障 503；资源版本冲突 409。不要把 KeyError 暴露成 500。
- 服务重启后 queued/running 检测任务进入可恢复或 interrupted 状态，不能永远显示加载中。
- 复用现有同源/会话写请求保护；证据下载只能访问已批准运行目录。

错误必须给出代码、阶段、资源、可读原因、下一步动作和是否可重试，不暴露原始环境变量。用户取消未保存表单和后台任务取消是不同操作；ESC 关闭详情不取消已经提交的操作。

## 9. 实施阶段与验收门槛

1. **可见性**：静态目录、真实绑定状态、环境、列表与详情、局部失败。
2. **可管理**：共享执行门禁、版本、撤销、运行快照、调用意图/结果。
3. **可扩展**：MCP 实际调用与生命周期、SKILLS 实际正文/附件注入。
4. **记忆一致性**：偏好、PG 资料用途、namespace、上下文、遗忘与恢复。
5. **完整验收**：42 项场景、真实 PG/MCP、响应式/键盘、单条新闻草稿链路和性能证据。

每阶段可独立展示进度，但在第二阶段之前不开放无执行约束的开关。在第三阶段之前不把已发现 MCP/技能说成已被智能体使用。

重点反例：停用写稿后子调用仍发生；退役技能后恢复换用新版；遗忘后旧摘要再次注入；HTTP 重定向泄漏 Header；不完整分页误判工具删除；接口只隐藏资料而检索仍命中；测试 namespace 修改生产摘要。

真实平台测试只保存/读回草稿，不公开发布。公开发布授权与平台限制不能借新增工具、MCP 或 Skill 绕过。测试使用独立 namespace，文件和浏览器产物全部放 E 盘；不用清空生产库来搭建测试。

性能目标仍为暖启动本地 PG 下 50 项目录 GET p95 <= 500ms，须列样本量。新增管理开销与模型/网络耗时分开，不能用不同输入或不同模型冒充提速对比。
