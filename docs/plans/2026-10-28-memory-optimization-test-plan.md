# 内存优化实施与测试计划

日期：2026-10-28。状态：代码与回归用例已编写，本计划尚未执行。对应 [优化设计](2026-10-28-memory-optimization-design.md) 与 [实施记录](2026-10-28-memory-optimization-implementation.md)。

## 1. 测试原则

- 本次只完成设计和只读检查；不得把后续测试列表标为通过。
- 不在当前仅约 1.19 GiB 可用内存的环境直接启动全量压力任务。
- 测试在 E 盘，使用独立测试目录/数据库 schema 与明确批准的测试 profile；不复制真实 Cookie、密钥进报告。
- 真正的 PostgreSQL/pgvector 验收不使用内存数据库兜底；小型单元测试替身只测试分支，不能替代实机验证。
- 所有平台实测默认保存草稿，不公开发布；重新执行涉及新生成/上传的测试前确认本次授权和范围。
- 不结束 CC Switch、Codex、Claude Code、默认浏览器或用户手动服务。

## 2. 基线与观测

### 2.1 三种运行状态

1. 冷启动：服务均未由本项目启动，启动 API 后不开任务，停留聊天页 10 分钟。
2. 热运行：做一次知识库查询、一次小批索引、打开草稿/图库，然后回到聊天页再空闲 10 分钟。
3. 任务运行：固定同一组材料分别生成 1 条与 10 条新闻；再测新闻 + AI 讯息 + 地图组合。

分别测独立智能体和工作流，避免只测工作流而宣称智能体改善。W/A 同时运行另设专项，不能混入单实例指标。

### 2.2 必记字段

| 类别 | 字段 |
| --- | --- |
| 环境 | 时间/时区、OS、总内存/可用内存、代码版本、未提交差异指纹、模型和依赖版本 |
| 配置 | generation pipeline、并发、图片模型、嵌入批次、图片硬门槛、查重/同步设置 |
| 进程 | PID、创建时间、父 PID、owner、进程角色、Private Bytes、工作集、峰值、线程/句柄/子进程数 |
| 业务阶段 | import、API ready、snapshot、collection、writing、image、review、save、readback、idle |
| 队列与资源 | 在途/待执行数、活动嵌入实例、浏览器/Node 数量、池连接数、缓存项数及字节估计 |
| 时间 | 端到端、实际工作、外部供应商/网络等待、内存保护等待；均保留原始时间戳 |

运行阶段每 5 秒、空闲每 30 秒采样；保留统一单调计时和北京时间展示。Windows Private Bytes 是提交量，不标成实际 RAM；工作集含共享页，不直接求和解释全部物理内存。PostgreSQL shared_buffers 单列，不将各 backend 中相同共享页重复计数。

先采优化前后各 3 次固定输入中位数及峰值。纯资源测试使用可重放的已保存材料/图片，排除收费模型和网络抖动；真实端到端另测，报告不可控变化。不得对两次不同新闻、不同模型的耗时直接计算代码提速百分比。

## 3. 单元与契约测试

| 编号 | 覆盖内容 | 通过条件 |
| --- | --- | --- |
| M01 | API/健康/配置的导入边界 | 新解释器中这些路径不加载 fastembed/onnxruntime；不能靠上一测试残留的 sys.modules 得出结论 |
| M02 | CPU 嵌入参数 | 小批/大批均 parallel=None，推理批 16/8，线程设置不扩大到全部核心 |
| M03 | 并发首次查询 | 竞争初始化仅构建一个模型，异常可重试且不返回半初始化对象 |
| M04 | 模型 manifest 校验 | 流式 hash 与旧版一致；篡改/损坏必报错，禁止跳过校验 |
| M05 | 分批摄入 | 6,000+ 文档处理窗口有界，长文档受 chunk/token 上界限制，不同时列表化所有 Post |
| M06 | 向量兼容 | 固定语料前后维度、模型 ID 和检索排序一致；批处理浮点差异使用明确容差，不把结果质量退化当作省内存 |
| M07 | 摄入中断/重试 | 保留已提交批，重复输入 counts/版本正确，无重复 chunk，无错误全量成功状态 |
| M08 | 历史 job 缓存 | 构造 10,000 个历史 job，启动只留有界摘要/活动态；仍能按 ID 访问最旧任务并找到全部未完成任务 |
| M09 | 事件窗口与增量 | 超过 600 条后游标仍单调；过期游标有显式重置/补读语义，不静默漏事件 |
| M10 | 图片响应峰值边界 | 大响应/非法 JSON/base64/超限均受控；接收不同时保有 chunks+join 的冗余副本 |
| M11 | 图片排队 | 未获执行槽前不读取/编码参考图；取消排队不泄漏锁/大对象；输入路径失败不误写 submitted |
| M12 | 既有安全契约 | 订阅路由、不切付费 API、不确定请求不重发、产物校验、缓存命中行为不变 |
| M13 | 资源所有权 | borrowed 不停止；owned 核对 PID+启动时间+路径；PID 复用和端口抢占均不误杀 |
| M14 | 双程序租约 | W/A 借用同一服务，一方完成不能关闭另一方正在使用的服务，最后租约退出才清理 |
| M15 | 压力准入 | 模拟正常/紧张/严重/恢复，触发滞后有效；已开始请求安全完成；没有新建全局耗时预算 |
| M16 | 降频和日志 | 终态/后台页不再高频全量刷新，折叠技术日志不序列化；切换页和卸载后清理订阅/object URL |
| M17 | 数据库池 | 各角色连接上限真实生效，空闲可缩小；迁移/应用权限隔离保留，异常不回落其他存储 |
| M18 | 原业务回归 | 模型选择持久化、大模型校准、关键词、图片参考门槛、部分合格上传、目标续跑均正常 |

每次源码编辑前重新执行 GitNexus impact；提交前执行完整 detect_changes，不把 partial/truncated 当作干净结果。先运行相关现有测试，再按修改公共范围扩展回归。

## 4. 实机模块测试

### 4.1 嵌入与 PostgreSQL

- 对 1、16、64、128 条输入采进程树，确认当前 FastEmbed 大批分支不再产生额外 spawn 模型实例。
- 采样模型加载、manifest 校验、推理、空闲峰值，分别统计，不能仅记录最后一刻。
- 在真实 PostgreSQL 写入/查询现有模型向量，并验证 namespace、用途过滤及旧向量兼容。
- 确认查询/索引不会重复构建模型；记录 API、runner、MCP 是否分别持有实例。
- `SHOW` 实际数据库参数，记录 pg_stat_activity 中各角色/进程连接数；数据库关闭、池耗尽和重连场景明确返回正确状态，不丢事务。
- 仅当 P0/P1 失败才测试 P2：空闲退出、下次查询冷启动、worker 崩溃、查询优先、跨 W/A 租约。

### 4.2 按需服务与浏览器

| 场景 | 必查结果 |
| --- | --- |
| RSSHub 首次启动、成功结束 | 最后租约释放后按宽限退出，无自身 Node 孤儿 |
| RSSHub 已手动启动 | 任务结束后手动实例仍运行 |
| RSSHub 启动失败/端口异常 | 保留已有启动时间边界，不启动多个实例，不误停占用端口的进程 |
| WorldMonitor 成功/超时/父任务取消 | 自有 launcher/子进程都释放，不出现可见窗口 |
| MCP 多次调用 | 复用已存在的 MCPRuntime，同次任务不会每次常驻新 server，空闲/任务结束按原契约关闭 |
| 小红书连续保存与回读 | 同 profile 串行批处理、浏览器不与生图等待长期重叠；终态后自有 context/页面退出 |
| 用户手动专用浏览器占用 | 仍明确提示，不能擅自关窗或改用默认 profile |
| 正在平台写入时触发严重压力 | 不能强杀；保存确认或进入可核对的不确定状态，绝不直接重新提交 |

正常退出、程序异常、取消和服务复用各跑一遍；单测 close 被调用，不等于实机子进程已退出。

### 4.3 React

- 使用浏览器 Heap/Performance 记录 10 分钟聊天页、10 次页面切换、100 次增量播报。
- 后台标签页 10 分钟后回前台，补齐状态而不丢目标/重复确认；请求数应明显降低。
- 对大历史会话、最早消息翻页和技术日志展开/折叠进行验证，DOM/状态窗口有界且历史可访问。
- 图库打开/关闭 20 次，检查原图解码、object URL 和 detached DOM；不将图片消失或缩图质量下降视为通过。
- 对比构建产物与首页请求，不额外启动 Vite 开发服务作为生产运行的必需常驻项。

## 5. 稳定性与端到端

1. 先执行不耗模型额度、无平台写入的固定材料 20 轮测试，比较预热后的空闲保留量趋势。
2. 在余量充分的环境，用 agent 单句完成 1 条新闻生成、审稿、保存草稿、平台回读。记录各阶段时间和峰值。
3. 经确认后，用 agent 单句完成 10 条新闻 + 1 条 AI 讯息 + 1 条全球地图；审核质量与交付数量与原契约一致，不以减少条目通过验收。
4. 在安全生成阶段暂停/重启后恢复，确认已完成文本、图片和审核复用；不在写入未决时主动制造强杀。
5. 使用注入式内存读数测试压力路径，真实物理压力验证须单独确认，不占满整机迫使其他重要程序退出。
6. 保留外部共享服务前后 PID/创建时间，证明 CC Switch/Codex/Claude Code 未被重启或改配。

如测试期间额度不足、信源不可用或账号受限，记录为外部阻塞，不假定内存优化失败；但仍检查现有产物保留和资源释放。若配置变更影响实际生成质量，必须单列为功能回归。
