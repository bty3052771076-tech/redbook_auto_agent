# 计划要求格式兼容修复

## 问题与原因

2026-10-10 的实际待确认计划包含 `topic_brief_strength=soft_preference`，而执行契约只接受 `preference`、`requirement` 或待选择值。模型还将查重、时效性、标题、配图、选题分布和事实核验输出成未支持的结构化约束。这造成两条字段错误，并使确认按钮禁用，属于格式映射问题，不是信源不足。

## 修复范围

- 明确别名 `soft_preference` / `hard_requirement` 分别归一化为 `preference` / `requirement`，不推测缺失的强度。
- 仅将严格符合 `{type, rule}` 且类型为 `dedup`、`freshness`、`facts`、`title`、`image`、`topic_balance` 的文字说明无损迁入补充要求，编译后传入生成提示词。已有相同文字不重复追加。
- 合并超过字段长度时保留原要求并阻断，不截断或丢弃；未知类型、多余键及无效内容继续保留并阻断。
- 已核对内容的摘要绑定仅在无损格式迁移时更新；用户改过但未核对的文本仍要求选择强度。硬性分类配额不因格式兼容而变成软偏好。
- 校准提示词明确字段枚举，输出 schema 只声明支持的篇数约束，不再鼓励模型发明约束类型。
- 编辑计划中逐项展示剩余结构化约束，提供具名移除按钮。移除并保存仍只是新修订，不执行任务。

宿主日期核验、事实审核、查重、禁止付费降级、冻结执行契约和人工确认边界均保留。文字说明传入生成与审核流程，不代表新增任意文字硬约束的保证能力。

## 验证结果

- 修复前：新增格式回归测试出现 5 个预期失败；未知约束移除浏览器测试因缺少控件失败。
- 修复后：针对性后端回归 79 项通过，浏览器回归 20 项通过；全量 `pytest -q tests` 为 483 项通过、1 项跳过、3 项现有依赖弃用警告，用时 175.33 秒。
- `npm run build` 通过，包括 TypeScript 检查和 Vite 构建。
- 回归覆盖全部文字要求保留、重复归一化、冻结契约、未核对文本、未知/畸形约束、长度上限、真实校准解析，以及编辑移除后可确认但未执行。
- 本地服务无活动任务后已重启。通过现有修订 API 将问题计划第 2 版保存为第 3 版；此前版本保留，全部原要求保留，字段错误清空，状态为 `ready`。
- 已在实际 GUI 验证“确认并执行”按钮可用。修复前后运行记录仍为 45 条，当前对话没有运行记录；未生成、上传、发布或同步额度。
