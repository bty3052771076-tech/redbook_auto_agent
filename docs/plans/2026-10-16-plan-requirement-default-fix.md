# 补充要求默认强度与AI羊毛字段修复

## 原因

1. 校准模型允许输出topic_brief_strength=null；计划契约将空强度作为必需人工处理项。
2. 计划编辑器每次修改补充要求都会清空强度。只显示默认单选按钮还不够，保存修改时也必须发送强度，以便后台将其绑定到新文本。
3. AI羊毛未列入可消费选题字段的栏目，且智能体生成适配器没有将job.prompt传给福利工作流。

## 修改边界

- 已支持选题的栏目，非空补充要求的强度缺失、null或空字符串默认preference。已有明确requirement不自动软化；未知值和未绑定的硬要求仍阻止执行。
- 保留强度与文本的绑定校验，不把旧的明确批准自动套到被外部修改的文字；前端人工改字时明确发送当前选择。
- 后台校准结构默认preference，提示词明确默认值；前端打开旧null候选、新增要求、继续编辑时均显示默认选择。
- AI羊毛接入检索词、选题偏向、补充要求和已明确保留的旧版要求；其编译提示词经CLI和智能体适配器进入实际福利采集。
- 用户检索偏好排在默认检索前，避免速度模式裁掉用户主题；厂商偏好只影响已核验福利的顺序，不删除其他厂商活动，不改变金额、领取条件和日期。
- AI羊毛不生成独立新闻评价，校准提示不提出评价视角；事实、日期、来源与无福利提示保持原策略，未知活动不编造。
- 不修改原工作流仓库、不安装依赖、不变更正式模型或数据库配置、不启动生成上传任务、不重启正式服务。

- 新测试覆盖默认、明确硬要求不软化、未知值不默认、文本绑定、旧null候选、编辑保存刷新、校准采用后加载，以及福利工作流实际参数和保留事实。
- 使用本地无窗口Chrome与受控HTTP；数据库使用E盘一次性PostgreSQL测试库。不会调用真实模型或操作小红书。

## 生效方式

正常重启独立智能体后端并刷新页面即可载入新逻辑。旧的未执行候选可重新采用或编辑保存，后台重新规范化，不需要为了选强度重新调用模型或重新生成新闻；既有已冻结执行不主动改写。
