## 1. 已实现

| 范围 | 实现 |
| --- | --- |
| 动态准入 | 新增轻量 `src/workflow/resources.py`；物理可用内存、提交余量、当前进程工作集/Private Bytes；按任务类型协调进程间许可，不改供应商上限 |
| 压力状态 | 5 秒采样窗口、连续低余量判定、恢复 30 秒后每 10 秒逐步增加容量；未知读数保守准入，不解释成零占用 |
| 在途保护 | 只等待新操作，不由内存保护强杀已经提交的模型/平台请求；保留既有 PostgreSQL 远端不确定请求占位 |
| 队列背压 | 现有 LLM/图片线程池增加有限待执行容量，结合图片/采集/嵌入/浏览器准入；不再预先无限提交闭包 |
| 嵌入模型 | 延迟 FastEmbed 导入、初始化单飞锁、CPU parallel=None、小批 16/8、流式模型文件校验，不替换模型或重建向量库 |
| 文档摄入 | 最多 32 篇一批；本地 SHA 清单与 PostgreSQL 文档版本一起核对，数据库缺失时不相信旧清单；变更文档用同份输入计算摘要和解析，避免缓存与正文错配 |
| 向量提交 | 一篇文档内生成器分批嵌入，同一数据库事务写完；异常整篇回滚，避免只写入部分 chunk 就被当作索引完成；加文档版本检查与无进展保护 |
| 图片 | 等待执行槽时不提前 base64 编码；响应使用单一有界缓冲；完成解码后释放响应/大字符串，保留原响应限制、产物校验与订阅/计费边界 |
| 历史任务 | 新增 `JobJournal`，活动任务保留，终态详情缓存最多 8 项/4 MiB；历史按需读取，列表按游标分页，损坏 journal 跳过；不删除旧文件 |
| 页面 | 聊天默认 50 条、可翻较早页；运行列表 50 条分页；技术日志展开后读取，完整日志仍可获取；草稿/运行列表按页进入加载 |
| 进度 | 运行摘要约 2 秒，后台页 15 秒；对话按 revision 避免重复加载，目标/上下文最多每 15 秒刷新；终态停止高频轮询，保留错误重连与前台补齐 |
| 按需服务 | 新增 `src/integrations/local_process.py`，RSSHub/WorldMonitor 共享租约；核对 PID、创建时间、可执行文件；借用用户服务不结束 |
| 取消与异常 | 正常退出及任务进程结束后回收无使用者的服务；Windows 取消保护其他活任务借用的服务子树，不再无条件对整棵树 `/T` 强杀；识别 PID 复用/旧父 PID 残留 |
| 观测 | `RunContext.record` 带内存样本；活动期间轻量采样写 runtime 日志，单进程文件 5 MiB/3 分片；没有活动时不保留额外采样进程 |
| 数据库池 | 空闲最小连接降至 0、60 秒缩容，支持按角色配置上限并在进程退出关闭；未修改 PostgreSQL 正式参数或主动缩小既有最大连接数 |

公共工具分别移植到了 `redbook_workflow` 和 `redbook_agent/tools/redbook_tools`；独立智能体的 API/React 分页改动仅在智能体仓库中。两套程序没有增加互相导入依赖，没有复制凭据和数据库。

新增模块的必要性：`resources` 只负责跨入口资源准入和轻量指标；`local_process` 统一两个已有按需服务的所有权回收，避免重复且不一致的停止逻辑；`JobJournal` 封装旧 journal 的有界读取。没有增加新调度器、数据库、Redis、付费模型路径或常驻模型服务器。

## 2. 采用的边界与有意保留

- 压力不足时只降低并行数/批次，不减少新闻条数、输出字数要求、事实审查或平台保存回读。
- 现有 MCPRuntime 的复用、空闲 60 秒关闭继续保留；没有另建 MCP 池。
- 无窗口小红书继续按专用 profile 串行保存；CC Switch/Codex/Claude Code 及默认浏览器不由资源模块管理。
- 与设计中的“宽限约 30 秒”相比，当前 CLI/最后租约退出立即回收自有 RSSHub/WorldMonitor，避免为等待宽限再保留一个辅助常驻进程；有其他活租约则不回收。
- 严重压力时可继续对已经加载的嵌入模型做有界小批推理，但不启动新的大模型加载、浏览器或大图请求，避免模型已加载后因过大的再次预留量产生自我阻塞。
- `P2` 短生命周期独立嵌入 worker 按设计保持条件实施，本次不提前增加。必须先比较 P0/P1 的实测结果。
- 当前原生内存样本记录调用进程；全浏览器/Node 子树峰值及数据库共享页需要随测试计划补充外部采样，不能把当前进程 Private Bytes 当作整机物理占用。
- 全部阈值/预留量仍需实测调节，不能宣称已节省 30% 内存或保证指定耗时。进程树终止、跨程序租约和真实 PostgreSQL 事务等路径尚未实机验证。
