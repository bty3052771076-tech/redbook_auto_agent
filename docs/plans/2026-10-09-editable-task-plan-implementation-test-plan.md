# 可编辑任务计划实施与验收计划

日期：2026-10-09（北京时间）。状态：设计验收规范，共61项核心用例；本次不实施或执行测试。当前工作树中的实现和已有测试记录不能替代逐项验收结果。

主设计：[可编辑任务计划与大模型校准](2026-10-09-editable-task-plan-design.md)。本文件定义后续编码顺序和验收，不记录尚未执行的成功结果。

## 1. 验收目标

让用户在原始指令、本地草案、模型候选之间判断任务意图，并直接编辑任务。语义差异不得让整个候选消失；执行必须与最终已确认修订一致。

验收分三层：

1. 计划与引用：模型输出能否转为可编辑候选，差异是否合理展示。
2. 编辑与存储：用户修改是否落入PostgreSQL，冲突和刷新是否可靠。
3. 工具契约：确认后实际 `AgentJob` 及任务请求是否准确接收到这些属性。

本功能验证不需要大批生成新闻。自动测试对外部模型和上传做隔离；实机验收只做一次任务校准和编辑保存。实际生成上传留到用户单独要求时进行。

### 1.1 用户场景的验收优先级

主设计第1.3节为最终决策顺序。以下是现有61项用例的优先检查路径，不新增模型裁决或新的验收编号：

| 优先场景 | 对应用例 | 不能缺少的断言 |
| --- | --- | --- |
| 规则10篇、模型8篇、用户最终5篇 | A02、A13、B01 | 模型不被规则值否决；最终保存、冻结和CLI消费均为5，不只检查侧栏 |
| 模型漏词或改写选题 | A03、A04、D01 | 候选仍可见，差异可编辑，不自动补回规则关键词 |
| r7引用错误 | A06、A08 | 核心候选保留；说明未核验，不要求用户修内部编号 |
| 删除旧偏向、新增原文没有的偏向 | B02、B03、B11、B13 | 人工修改可保存；再次校准和辅助记忆不能恢复已删除的要求 |
| 修改和采用后尚未确认执行 | C01、D07、D09 | 无生成、图片或平台副作用；未保存值不能成为实际执行值 |
| 计划有效但新闻材料不合格 | E01、E02及既有工作流质量测试 | 用户确认不授予新权限，也不关闭日期、查重或事实核验策略 |

以上设计检查不构成产品测试结果。实施报告需逐项附实际证据，未运行的用例保留“未验证”，不能凭完成设计或已有代码改动标记通过。

## 2. 编码前检查

- 查看当前工作树，保留已有能力中心等改动；不借本任务重写无关模块。
- 核实实际Python导入路径位于独立智能体工具副本，前端构建与服务使用同一版本。
- 对准备修改的符号执行GitNexus impact；HIGH/CRITICAL须明确报告，UNKNOWN须核对实际调用入口。
- 阅读现有校准、证据引用、Schema兼容、主题偏好、CLI计划加载和会话并发测试。
- 确认测试PostgreSQL实例/命名空间；数据库失败直接使集成测试失败，不能退化为内存伪通过。
- 不安装新依赖，不改API Key，不同步额度。日志、截图、临时文件放运行区 `data/tmp/task-plan-editor/`。

## 3. 分步实施

### P1：统一计划契约与执行编译

涉及：新 `src/agent/plan_contract.py`、前端Plan类型、原计划的兼容读取。

- 定义v3计划、稳定栏目ID、检索词与选题偏向、人工覆盖和字段问题。
- 实现纯函数编译结构化字段到现有 `AgentJob` 参数。
- 分清未提供、显式空数组、清空说明、移除栏目。
- 对旧v2计划提供读取适配和首次编辑的显式迁移；不能丢掉旧附加要求。
- 测试：同一输入得到稳定编译结果，删除主题后编译文本无旧主题，旧脚本仍能加载原格式。

完成门槛：展示属性和编译后的执行字段存在可测试的一一映射。

### P2：校准服务职责调整

涉及：`task_recognition.py`、相关提示词与识别记录。

- 模型输入使用原始指令和人工覆盖，不传入正则语义结果作为答案。
- 核心计划解析与附加说明验证分开，支持可编辑的字段错误。
- 数量/主题差异改为可查看变化，移除“必须等于正则”的拒绝分支。
- 引用错误产生非阻断诊断；v3引用仅输出编号，服务器回填来源文字。
- 真实格式错误继续失败并保留原计划；不能从截断JSON或任意说明中猜执行对象。
- 一次调用、无自动重试、无副作用和计费策略保持现有约束。

完成门槛：能复现旧拒绝案例，再让新实现返回带提醒的候选；不能通过简单删除所有校验来通过测试。

### P3：计划修订API与PostgreSQL

涉及：新 `backend/plan_service.py`、`backend/app.py`、既有会话存储。

- 新增保存修订接口；扩展候选采用为有限字段编辑。
- 原模型编辑路由委托统一修订服务，兼容旧客户端。
- 保存只创建新修订；记录来源、差异、清空和删除操作。
- 使用会话修订号和计划版本，完成幂等、跨会话限制和冲突返回。
- 候选基于过期输入时不可自动采用；数据库故障不假保存。
- 计划执行认领与同一幂等ID的恢复规则必须实现并验证，不能只依赖进程内锁。

完成门槛：两个独立数据库连接并发保存/提交，最多一个当前修订或一个运行，另一方得到明确冲突或同一结果。

### P4：React计划编辑器

涉及：`PlanEditor.tsx`、`TaskCalibration.tsx`、`PlanModels.tsx`、`App.tsx`、`api.ts`及局部样式。

- 增加“编辑计划”和“编辑候选”，共享抽屉表单。
- 数量步进、栏目增删、偏好和检索词标签、补充要求、评价视角、模型及运行选项均按主设计实现。
- 原始指令、当前值和候选差异可查看；人工修改在来源状态中可辨认。
- 保存与执行分离；未保存修改、服务端保存失败时不可运行页面上尚未保存的新值。
- 支持中文输入法、键盘、窄屏、长标签换行、字段定位和刷新恢复。

完成门槛：用户无需重新发送整段话，就能把10篇改为5篇并修改多个偏向。

### P5：冻结和执行路径

涉及：`Workbench.execute_agent_plan`、CLI计划读取、当前任务约束摘要。

- 使用保存修订的语义摘要，执行前再次检查版本、实际能力及模型绑定。
- 冻结结构化字段、编译结果和确认身份；实际工具读取一致数据。
- 原始指令和历史记忆不能把删除偏好重新合并回本次任务。
- 续跑继续冻结版本；新编辑创建新计划，不改运行中的参数。
- 旧人工CLI/GUI和工作流目录继续可用，平台上传串行规则保持原实现。

完成门槛：只拦截外部任务启动，在真实冻结文件和真实CLI加载器处检查字段，而非仅检查前端JSON。

## 4. 核心验收用例

### A. 校准与语义

| 编号 | 输入/操作 | 预期 |
| --- | --- | --- |
| A01 | 完整原句含10条、6类偏好、约3条、不设硬配额 | 比例进入说明，主题进入偏好，存在可编辑候选 |
| A02 | 规则错误识别10条，模型理解为5条 | 展示10到5的差异，不以正则结果否决模型 |
| A03 | 模型漏掉一项显式检索词 | 候选仍展示，列出移除差异；用户可加回或接受删除 |
| A04 | 模型把主题换为同义表达 | 作为模型建议展示，不冒称逐字原文，不强制重试 |
| A05 | 原文不上传，模型建议平台草稿 | 当前交付不自动改变；用户看见差异并选择后才能保存/执行 |
| A06 | 模型要求r7引用编号加错原文 | 核心候选保留，该说明为待核对，不显示已核验来源 |
| A07 | 引用ID有效但解释明显跑题 | 只证明来源可定位，界面允许用户判断/修改，不能宣称语义验证成功 |
| A08 | 引用ID不存在 | 记录未核验诊断，不捏造原文，不丢掉其余核心计划 |
| A09 | JSON截断、重复键、根为任意HTML | 解析失败，原计划可编辑，模型调用不自动增加 |
| A10 | 核心字段数量越界、栏目重复 | 字段错误可定位并编辑，修复前不能执行 |
| A11 | 附加说明字段格式错误 | 错误限于该说明，不使可解析计划整体丢失 |
| A12 | 原文或人工直接输入“必须2条某类”，未调用校准 | 人工选择强度并绑定约束；缺少强度或不支持的硬约束为needs_input，不能默默放宽 |
| A13 | 原文、本地规则草案与模型理解故意不同；拦截真实校准请求的网络发送位置 | 模型收到原始指令、已保存人工覆盖及公开能力/默认值，不收到规则数量或关键词作为答案；解析后差异只用于对比，不触发规则等值拒绝 |

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| B01 | 数量10改5 | 新修订、冻结文件、CLI AgentJob、运行请求一致为5 |
| B02 | 删除“隐私与年龄核验”，新增“游戏退款” | 保存后的标签和实际prompt一致；旧词不再从规则结果回填 |

| B05 | 修改补充要求并清空原说明 | 新执行prompt不拼接旧topic_brief或旧prompt |
| B06 | 同时存在检索词和偏好 | 两类字段互不污染，各自进入正确执行位置 |
| B07 | 新增AI讯息，删除每日新闻 | 新闻栏目不会被原文或规则重新补入；AI集合稿固定1篇 |
| B08 | 新闻与AI各有偏好 | 保存及执行时栏目间不串用要求 |

| B11 | 人工修改后再次校准 | 修改作为输入覆盖；旧候选无法自动恢复被删项 |
| B12 | 人工5篇，模型结构化建议8篇；用户逐项选用，或另行输入6篇 | 默认仍为5；选用后为8；直接编辑后为6。新修订保留差异与更新后的人工覆盖，过期基础值不能采用 |
| B13 | 当前任务的历史记忆含旧偏好 | 冻结约束优先，记忆不改变已确认数量/选题 |
| B14 | 恢复历史计划后再次校准 | 重新计算人工覆盖和栏目删除记录，不回到恢复前的值 |
| B15 | 强度已确认后修改补充说明 | 旧摘要的选择不能批准新内容，按新字段重新核对 |

### C. 存储、并发与恢复

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| C01 | 仅保存或采用候选 | PostgreSQL有新修订，外部worker、图片、浏览器调用为0 |
| C02 | 双击保存、网络断开后同幂等键重试 | 返回同一修订，不重复写消息/计划 |
| C03 | 两标签页基于同版本保存 | 一方成功，另一方409；未保存输入可保留 |
| C04 | 校准等待中用户保存修改 | 返回候选过期，不能覆盖当前修订 |
| C05 | 非语义状态更新引起会话revision变化 | 不盲覆盖；安全重读并核对相关输入，处理明确冲突 |
| C06 | 跨会话plan或候选ID | 拒绝，无另一个会话数据泄露/变更 |
| C07 | PostgreSQL断开 | 保存失败且不能执行，恢复后由用户重试 |
| C08 | 服务重启 | 保存的编辑可恢复，未结束校准显示中断，无自动付费调用 |
| C09 | 并发点击确认/不同进程确认 | 同一修订最多一个运行，返回同一run或冲突 |

| C11 | 已执行计划编辑 | 原计划冻结，只能另建修订用于新任务 |
| C12 | 断点续跑期间存在新编辑计划 | 续跑使用旧冻结摘要，不重新解析新消息 |
| C13 | 旧模型编辑API保存 | 使用统一修订语义，旧客户端仍能收到新plan |
| C14 | 保存与确认在两个独立进程同时提交 | 事务顺序决定胜者；旧确认409或编辑遇已冻结，不能混用两个修订 |
| C15 | 已成功操作同键同载荷重试，但当前版本已递增 | 返回原结果；同键不同载荷409 |
| C16 | 冻结数据库快照已提交，但文件缺失或不完整 | 从同一快照重建并核对哈希，不产生新任务或不同参数 |

## 5. 实际验证路径

### 5.1 固定回归输入

使用以下场景，模型返回由固定样本驱动；断言业务结果，不把实现细节复制进测试：

```text
生成10条今天的每日新闻，速度优先，保存到小红书创作者中心草稿箱，不公开发布。
每日新闻优先关注知名平台禁令与解禁、隐私与年龄核验、账号规则变化、游戏订阅退款、消费者权益争议、真实且有意外转折的社会事件。
每日新闻优先筛选知名主体发生意外变化并涉及普通人规则或权益的事件，约3条作为软偏好，不设硬配额，其余兼顾国际冲突、科技产业、社会民生、财经产业。
```

用户编辑为5篇、移除“隐私与年龄核验”、新增“游戏退款”、调整评价视角。测试检查UI、PostgreSQL修订、冻结文件、CLI读取结果四处一致。

该固定输入还用于复现用户截图中的两个问题，不另增模型裁决步骤：

- 对应A03、A04、D01：固定模型候选遗漏“隐私与年龄核验”或改写为“平台身份验证”。候选必须可见并可编辑；差异只能作为提醒，不能因与规则关键词不等而使整个候选失败。用户明确接受删除后，冻结计划和真实CLI输入不得重新恢复该项。
- 对应A06、A08、D02：固定模型返回错误的 `r7` 引用或不存在的编号。可解析的核心候选保留，只将相关说明标为待核对；用户无需手工修内部引用，即可编辑合法字段、保存并刷新。另用损坏JSON验证真正的解析失败仍保留原计划。
- 对应A13、B01、B03、C01：检查发送给模型的真实请求，再按“改为5篇、新增原文不存在的游戏退款、保存并采用”操作。模型请求中没有规则答案，保存阶段外部执行调用为0，确认后实际工具参数完全来自最终修订。

针对截图还需在上述用例内检查：关键词遗漏不再使用阻断性的 `TASK_LLM_INVALID_OUTPUT`，且候选值没有被规则结果偷偷补回；引用编号错误只影响相应说明，不把核心候选清空。两份计划字段一致时，不显示“已核验需求”或“新闻真实性已确认”。重复提醒只显示一次，侧栏不把原指令、规则归纳和编译prompt重复展示为多段选题偏向。这些是A03、A06、A13、D01的补充断言，不另增用例或模型调用。

差异提醒、字段问题、候选状态以及保存结果分别断言，不以“页面不再显示红色错误”作为通过依据。每项记录截图、保存修订身份和执行契约证据，不能只截取侧栏文字证明工具已经收到新值。

与主设计的校验边界对应，A02、A03、A04、A13必须同时检查：差异没有触发语义拒绝、候选未被规则值自动补回、用户仍能编辑。A06至A08检查来源定位，不宣称模型理解已正确；A09、A10及E01至E03检查必要的格式和能力门禁仍在。D01、D02、D08检查问题类型与可操作提示，理解差异或引用待核对不伪装成执行失败。

手工修改后的B01至B06必须检查保存值、刷新值和执行消费者三处一致，而不只检查页面标签。已有测试结果、未加载新代码的服务页面和仅使用固定模型响应的测试，都不能代替本功能的新实机校准记录。
